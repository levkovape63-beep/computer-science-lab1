# Лабораторная работа №2

## Анализ веб-приложения и клиент-серверного взаимодействия

## 1. Исследуемая информационная система

В лабораторной работе исследуется веб-приложение интернет-магазина Ozon. Оно позволяет клиенту найти нужный ему товар, используя поисковую строку и фильтры, а также добавлять понравившийся товар в корзину, в последствие выбрать удобный ему пункт выдачи и заказать.

Исследование является продолжением лабораторной работы №1. В качестве цифрового сервиса используется Ozon, а пользовательский сценарий остаётся прежним: выполнить поиск необходимого товара, открыть ему страницу и добавить в корзину.

Основными компонентами исследуемой системы являются:

**браузер** — обеспечивает взаимодействие пользователя с веб-приложением;
**Клиентская часть** — отвечает за отображение интерфейса и обработку действий пользователя;
**API\** — интерфейс взаимодействия клиентской части с серверной частью приложения;
**Сервер** — обрабатывает запросы и формирует ответы;
**хранилища** — используются для хранения информации о товарах, пользователях, корзинах и других объектах системы;
**внешние сервисы** — дополнительные компоненты, необходимые для работы отдельных функций веб-приложения.

После обработки запроса сервер вернул ответ со статусом `200 OK`.

В исследуемом ответе параметр `data.success` имеет значение `true`. Это означает, что сервер сообщил об успешном выполнении операции добавления товара.

![HTTP-ответ сервера](images/screenshots/6.4 HTTP-ответ сервера.png)

### 6.5. Результат взаимодействия компонентов

Таким образом, при добавлении товара в корзину происходит следующая последовательность:

1. Пользователь нажимает кнопку **«Добавить в корзину»**.
2. Frontend обрабатывает действие пользователя.
3. JavaScript формирует HTTP-запрос `POST`.
4. Запрос отправляется на API Ozon по адресу `/api/composer-api.bx/_action/v2/addToCart`.
5. В теле запроса передаются идентификатор товара и количество товара.
6. Backend обрабатывает полученный запрос.
7. Сервер возвращает ответ со статусом `200 OK`.
8. В JSON-ответе присутствует `data.success: true`, что указывает на успешное выполнение операции.
9. Frontend получает ответ и обновляет состояние корзины и соответствующий интерфейс.

Исследование показывает взаимодействие клиентской и серверной частей веб-приложения через API. Пользователь непосредственно не взаимодействует с Backend: действие выполняется через интерфейс Frontend, который формирует HTTP-запрос и передаёт его серверной части. Полученный от сервера результат затем используется клиентской частью для обновления состояния приложения.

## 8. Схема взаимодействия компонентов

На основе проведённого исследования была построена схема взаимодействия компонентов веб-приложения Ozon для сценария добавления товара в корзину.

На схеме представлены следующие компоненты:

- пользователь;
- браузер;
- frontend;
- API;
- backend;
- хранилище данных.

Последовательность взаимодействия компонентов выглядит следующим образом:

1. Пользователь выбирает товар и нажимает кнопку «Добавить в корзину».
2. Frontend, работающий в браузере, обрабатывает действие пользователя.
3. Браузер отправляет API HTTP-запрос методом `POST` по адресу `/api/composer-api.bx/_action/v2/addToCart`.
4. В теле запроса в формате JSON передаются идентификатор товара и его количество.
5. API передаёт запрос на обработку серверной части приложения (Backend).
6. Backend обрабатывает операцию и формирует ответ.
7. Сервер возвращает HTTP-ответ со статусом `200 OK`. Ответ содержит данные в формате JSON, в том числе признак успешного выполнения операции `success: true`.
8. Ответ передаётся через API обратно в браузер.
9. Frontend обрабатывает полученный ответ и обновляет интерфейс, отображая результат операции пользователю.
